目的:声の違和感の原因が「モデルの古さ」か「読ませ方(仕組み)」かを切り分ける。
対象:もこの冒頭3文(表紙・1・2)。**本番には使っていない**(テストのみ)。
`toolbox/narration-rules.md` への追記は、聞き比べの結果が出てから行う。

## 事前に確かめたこと
- モデルID:**`eleven_v4`**(速い版 `eleven_v4_turbo` もある)。今の API キーには `models_read` の権限がなく、モデル一覧(GET /v1/models)は使えなかった。ID は ElevenLabs の公開 API 仕様(api.elevenlabs.io/openapi.json)の列挙と、公式ドキュメントの検索結果で確かめた。実際に `eleven_v4` で生成できた
- 声 Shizuka(WQz3clzUdMqvBf0jswZQ):v4 で使えた。ただし声の情報の「高品質のモデル」の一覧に載っているのは turbo_v2_5 / flash_v2_5 / multilingual_v2 だけで、v4 は載っていない
- 文字ごとの時刻:`/with-timestamps` で v4 でも取れた(B・C とも全文字に時刻あり)
- 話し方の指示:TTS の API には指示を渡す専用の項目がない。**本文の頭に角かっこのタグ `[...]` で書く**(音声タグ)。C ではユーザーの指示文を日本語のまま入れた。タグの部分は時刻上 0〜0.2 秒にまとめられていて、読み上げられてはいないように見える(耳でも確かめる)
- `<break>`(SSML)は v4 では使えない(公式ドキュメント)。速さ・style のスライダーも v4 には無いとされている。B で speed 0.9・style 0.2 を送ってもエラーにはならなかったが、効いているかは不明
- stability 0.9・seed・previous_text / next_text は v4 でもエラーなく受け付けた
