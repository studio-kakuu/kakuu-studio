### なしの競技の提案
- **柔道**:コードで作ると、2人の動きを手で作るので時間がかかり、形もぎこちなくなりやすい。**おすすめは案B(外す)。** 代わりに入れるなら、データのある **ボクシング**(13_17・14_01〜14_03・15_13 など。武道の回の「打つ」動き)
- **弓道**:動きが少なく、ほとんどが静止なので、手で作っても品質を保ちやすい。**おすすめは案A(コードで作る)。** 「離れ」の瞬間の衝撃波とスピード線が、静けさとの対比で見せ場になる(**決定:コードで作る**)
- **剣道**:代用の振り下ろしで作れるが、本物らしさは一段落ちる。作ってみて弱ければ外す

## 3. 作り方(AI動画は使わない)
1. **動きのデータ**:CMU のモーションキャプチャ(BVH・120fps)から、競技に合うものを選ぶ(0章)。使うファイルだけ `videos/kakuu-games/mocap/` に置く(出典と利用条件は `works/kakuu-games/SOURCES.md`)
2. **拍に合わせる**(`videos/kakuu-games/build_event.py`):
   - どのデータも同じコマの骨の長さで動かす(人ごとの背丈の違いを合わせる)
   - 設計は「拍」で書く(テーマ曲の 130BPM で秒に直す)。ドリブルは手が一番低い所を拍に、シュートは頂点を小節の1拍目に置く
   - 解放の拍の直後に、同じ姿勢を3コマ止める
   - 2つのデータのつなぎ目は、関節の回転を 0.3〜0.4 秒かけて混ぜる。向きと位置は前の続きから始める
   - ボールの位置(ドリブル・持つ・放つ・次のボールが弾んで現れる)も同じスクリプトで出す
3. **コマの3Dモデル**(`video/remotion/src/kakuu-games/koma3d.ts`):角の丸い箱・太さの変わるカプセル・輪などの部品を組み合わせ、各部品を1本の骨にくっつけて、骨の回転で動かす。塗りは3段のトゥーン、輪郭線は裏面を少しふくらませて黒で描く
4. **映像**(`video/remotion/src/kakuu-games/Event.tsx`):Three.js を @remotion/three で Remotion の中に置き、1コマずつ決まった絵を描く。スピード線だけは画面の上に重ねる絵(SVG)。ヘッドレスの Chromium の WebGL(`--gl=angle`)で書き出す

### 案1:本物の動きのデータは、無料で使える
```
アニメ調の3Dのキャラを、スポーツで動かしています。
動きは手で付けず、大学が無料で公開しているモーションキャプチャのデータを使っています。
ドリブル、シュート、空手の型まで、2,500本くらいある。

I'm making an anime-style 3D character play sports.
Instead of animating by hand, I'm using free motion-capture data released by a university.
Dribbles, shots, even karate forms. There are about 2,500 clips.
Besides generating video with AI, combining old free resources is another path.
```

### 案2:拍に合わせるために、動きの速さを変える
```
曲は130BPM。1拍0.46秒に、動きを合わせたい。
でも本物のドリブルは、だいたい0.87秒に1回で、拍に合いません。
そこで、手がいちばん低くなる瞬間を拍に置いて、その間の速さを少しずつ変えました。
シュートの頂点は、小節の1拍目に。人の動きに、あとから拍を通すような作業でした。

The music is 130 BPM, so each beat is 0.46 seconds.
But a real dribble takes about 0.87 seconds, which doesn't fit.
So I put the lowest point of the hand on each beat and adjusted the speed in between.
The top of each shot lands on the first beat of a bar. It felt like threading a beat through human motion.
```

### 案3:データがない競技を、どうするか
```
14競技のうち、弓道と柔道は、使える動きのデータがありませんでした。
弓道は動きが少ないので、腕の角度をコードで作ることに。
柔道は2人で組む動きなので1人分のデータでは作れず、データのあるボクシングに替えました。
全部そろえるより、データがある所とない所を見極めるのが、最初の仕事でした。

Out of 14 sports, kyudo and judo had no usable motion data.
Kyudo has few movements, so I'm building the arm angles in code.
Judo needs two people grappling, so I swapped it for boxing, which has data.
Before building anything, the first job was figuring out where the data exists and where it doesn't.
```
