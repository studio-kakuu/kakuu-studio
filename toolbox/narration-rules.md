# ナレーションのルール(ElevenLabs)

ナレーション付きの作品で声を作るときの決まり。別プロジェクトの教訓をまとめたもの。
クレジットの扱い(キーを表示しない・本番以外は事前に確認する)は `CLAUDE.md` の「有料クレジットを使う生成」に従う。進め方は `CLAUDE.md` の「標準の制作フロー」のゲート2。

## 1. 設定(2026-10-09 から:Eleven v4)
- モデル:**`eleven_v4`**(Eleven v4)。旧モデル `eleven_multilingual_v2` は使わない
- **速さのつまみ(speed)は使わない**(v4 では効くかどうかが不確か。設定しない)。声の雰囲気・速さ・間は、下の「話し方の指示」で出す
- **話し方の指示**:v4 の音声生成の API には指示専用の項目がないので、**読ませる文の頭に角かっこのタグで自然言語の指示を書く**。例:`[寝る前の絵本の読み聞かせのように、やさしく、あたたかく、間をたっぷりとって]`。必要なら文の途中にも短いタグを置ける(使いすぎない)。タグは読み上げられず、時刻データでは ごく短い区間(約0.2秒)にまとめられる。生成後、タグを声に出していないか耳で確かめる
- `<break time="…" />`(SSML)は v4 では使えない。間は話し方の指示・句読点・空行・「……」でつくり、足りない分は録音のあとに動画側で足す
- stability:0.9/similarity:0.75(テストで問題なく受け付けた)
- seed:**固定の番号を毎回同じに使う**(作品ごとに `works/<作品名>/tools.md` に番号を記録する)。v4 は同じ seed でも完全には同じにならない
- 生成は `POST /v1/text-to-speech/{voice_id}/with-timestamps` を使い、**1文字ずつの時刻** を受け取って保存する(v4 でも取れる)
- 声:作品ごとに決める。Shizuka(WQz3clzUdMqvBf0jswZQ)は v4 で使えることを確かめ済み(声の情報の「対応モデル」一覧に v4 は載っていないが、生成できた)
- 消費クレジット:2026-10-09 のテストでは、v4 は送った文字数の **約 1/10**(175 字で 19)だった。台本案の見込みは「文字数 × 0.1〜1」の幅で書き、生成後に実際の消費を記録する

## 2. 生成のしかた:全体を1回で通す
- **ナレーションは全体を1回で通して生成する**(文ごとの分割生成はしない)。声の大きさ・声色・つながりがそろい、話し方の指示も全体にかかる
- 文と文の間は空行で区切る。場面の区切りは文字ごとの時刻で決める
- **文字ごとの時刻は、画面の文字が出る時刻と、場面の切り替えの位置に使う**(4章)
- Web の絵本の「よみきかせ」ボタン用の音声は、この1本から時刻でページごとに切り出す(各ページの最初の声の少し前〜最後の声の少しあと)
- 1回で通した声の「間」が映像に足りないときは、録り直さずに、時刻で切り分けて動画側で間を足す
- 2026-10-09 の録り比べ(`works/moko/audio/test-v4/README.md`)で、「v4+自然な日本語+話し方の指示+1回通し」が いちばん自然だった

## 3. 「画面の文字」と「読ませる文」を分ける
**画面の文字**(ひらがな中心・絵本の表記)と、**読ませる文**(声に渡す文)は、別々に持つ。
- **読ませる文は、崩さず普通の漢字かな交じりの自然な日本語にする。** 助詞の「は」「へ」もそのまま(「わ」「え」に書きかえない)。カタカナ化・読点の足しすぎもしない
- 画面の文字はひらがなのまま。読ませる文とは文字数が合わないので、画面の文字の1文字ずつの時刻は、読ませる文の時刻から割り当てる(文ごとに、読み始め〜読み終わりの間で対応させる)
- **読み間違いが出た語だけ**、その語に個別に対応する(読み辞書=pronunciation dictionary、読みを示すタグ、言いかえ)。文全体を崩さない
- ゲート2では「画面の文字」と「読ませる文」を並べた対照表、話し方の指示の全文、個別に対応した語とその理由、消費クレジットの見込みを出して止まる

### 旧ルール(multilingual_v2 向けの対策・v4 では使わない)
次の3つは、旧モデル `eleven_multilingual_v2` の読み間違いと単調さへの対策だった。**v4 では使わない。**
- 読ませる文を **ひらがなに崩す**(「は→わ」「へ→え」、名前・小さい「っ」のカタカナ化、読点の足し増し)。旧モデルの Shizuka では漢字で読み間違いが出たため(雲の子→「りゅうのこ」、風→「ふう」など)
- **文ごとに生成** して `previous_text` / `next_text` でつなぐ。旧モデルでは全体1回だと単調になったため
- **speed を下げる**(0.9 など)。旧モデルでは全体1回で speed がほぼ効かなかった
- 将来 v4 で読み間違いが出たら、上のように **その語だけ** を読み辞書やタグで直す(全体を崩す方法には戻らない)

## 4. 映像との合わせ方
- 場面の切り替えは、**前の場面の最後の声と、次の場面の最初の声の中間** に置く。読み終わる前に場面を変えない
- 画面の文字の「1文字ずつにじみ出る」演出は、できればナレーションのタイムスタンプに合わせ、**読まれるのと同時に文字が出る** ようにする
- **声が終わったあとは、絵が動く見せ場を残す**(風が吹く・雨が降り続く・花が次々ひらく・虹がかかる など)。何も動かない待ち時間は作らない
- 読み聞かせの作品の尺は **75〜90秒** を目安にする(61秒以上は必ず守る)

## 5. 文字の置き場所
- 絵本の文字やテロップは、各 SNS のボタンや説明文に隠れない位置に置く(1080×1920 の目安:上 220px・下 420px・右 160px には大事な文字を置かない)
- 表紙の題字と「AI と コードで つくった えほん」などのフック文字は、**最初のフレームから見える** ようにする

## 6. 音声ファイルの扱い
- 作った音声ファイル(とタイムスタンプの JSON)は作品フォルダに保存して再利用し、**同じ内容で二重に生成しない**
- 使った声の名前・ID・モデル・設定・seed・文字数(消費クレジット)を `works/<作品名>/tools.md` に記録する
